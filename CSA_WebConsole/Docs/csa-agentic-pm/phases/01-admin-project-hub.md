# Phase 01 — Admin project hub and internal projects

Prerequisite: phase 00 has established actual project schema and migration conventions. Read CONTRACTS.md and UI_SPEC.md. Deliver only the basic PM hub; AI and terminal remain disabled.

## IDE AI work

1. Add project scope and minimal PM metadata to existing app.projects, reusing columns already present. Backfill every existing tenant project as client-scoped. Keep all existing IDs, channels and lifecycle values.
2. Audit nullability, indexes and caller assumptions before allowing internal projects without client_id. Add the scope/client constraint and internal-slug uniqueness; preserve tenant-slug uniqueness. Explicitly exclude internal projects from client counts and portal queries.
3. Add a shared access resolver and project service. Retain existing endpoints through their existing contracts or thin service wrappers; do not introduce divergent project implementations.
4. Add `/api/admin/pm/projects` list/create and project detail/update with admin guards, pagination, version conflict handling and audits. Validate client IDs using the existing read-only domain engine. A client creation request whose domain lookup is unavailable should return a clear dependency error rather than silently switching scope.
5. Add `/projects` and `/projects/[id]` inside the current admin shell. Include client/internal filters, creation drawer, overview, empty/error states and links to existing channel configuration. Extend command palette navigation.
6. Add `PM_ENABLED` and independent future feature flags through existing settings conventions. Disabled backend routes fail closed; hidden UI alone is insufficient.

## Changed boundaries

Expected: project model/migration, existing project services/callers, new PM router/service, AppShell navigation and PM page components. Exact paths come from phase 00. Use existing session dependencies and kit primitives.

## Acceptance checks

- Existing client project/channel fixtures migrate with stable IDs and remain visible at the same portal URLs.
- Admin can create one internal project and one project for an existing client.
- Client A cannot list/open Client B's project or any internal project through old or new endpoints.
- Creating an internal project through a tenant API is rejected regardless of body fields.
- Duplicate slug behavior is correct separately for a client tenant and internal scope; lifecycle remains setup/active/archived.
- Concurrent PATCH fails with conflict for a stale version, and privileged writes are audited.
- Client counts and agent/project metrics do not count internal projects accidentally.
- Existing project tests and changed backend/frontend checks pass.

## Operator work

Review migration SQL generated by the existing migration tool. Back up the app DB before applying it to staging/production. Enable PM only for admins after the hub passes smoke checks. Disabling the flag is the first rollback; do not drop populated PM metadata to undo a UI release.
