# Pictures Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A company uploads one picture for its DuitNow QR method, each plan and each product (the training library generates one per video); the bot sends that picture on Telegram, as its own message before the text, when that one thing is the subject of a reply or a payment reminder; staff see it in the Inbox.

**Architecture:** One shared store in Postgres (`media_assets` metadata, `media_asset_data` bytes, migration 0610) behind a small `csa/media` package: an image check that reads only headers, `put/get/delete/delete_for`, one read route with a per-kind policy table, and upload routes that live in each owner's router and mirror its write rule. Sending reuses the outbox: an agent sets `AgentResultData.picture`, the coordinator turns the first one into an extra `OutboundMessage(kind="image")` stored with an `attachments` entry, both rows get `created_at = clock_timestamp()`, and the delivery worker reads the bytes at send time and posts multipart `sendPhoto`, giving up after two attempts as `skipped` so the text always follows. PR 2 ships in two deploys: readers (2a), then emitters (2b).

**Tech Stack:** Python 3.12, FastAPI, psycopg 3 async with SQL under `db/sql/`, PostgreSQL with RLS, httpx (Telegram Bot API), LangGraph coordinator (`csa/graph/coordinator.py`), the hardened ffmpeg child of `csa/training/media.py`, Next.js console (`CSA_WebConsole/csa-console/web/`), node `--test`, Playwright. No new dependency (no Pillow: dimensions come from the JPEG/PNG headers; tests build images byte by byte).

**Spec:** `docs/superpowers/specs/2026-11-15-pictures-design.md` (approved by the owner 2026-11-15; binding, including section 14). Related: `docs/superpowers/specs/2026-11-15-payments-followups-survey.md` section D. Code facts below were re-read on this branch (main 7fd92cd5 + the design); where the plan settles something the spec left open or got wrong, the task says so under **Decided here**.

## Global Constraints

- Kinds: `payment_qr|plan|product|training_thumbnail`. `subject_key`: the payment method id, the plan code, the product id, the training item id, as text. Unique `(client_id, kind, subject_key)`: one picture per subject; replace is an upsert that keeps the row `id` and changes `sha256`, which is the version and the `ETag`.
- Upload rules: JPEG or PNG only, extension and magic bytes agree, at most **2 MiB** (2097152 bytes), each side **64-4096 px** read from the header and the longer side at most **10 times** the shorter (a conservative guard: Telegram's own ratio limit is unverified, from general knowledge about 20:1), one file per request (`upload_form`, `max_files=1`, field `file`), refused for `read_only`, CSRF as every console write. At most **300 pictures per company** (409 `picture_limit`).
- Migration range **0610-0619**; one file, `db/migrations/0610_media_assets.sql`; `EXPECTED_SCHEMA_VERSION` (`apps/gateway/main.py:74`) `"0601"` -> **`"0610"`**. Tests read the constant; none hardcodes a version.
- Routes and roles (spec section 6): `PUT|DELETE /console/v1/payments/methods/{id}/picture` admin only, `qr` methods only (422 `picture_kind_not_qr`); `PUT|DELETE /console/v1/subscriptions/plans/{code}/picture` platform_admin, tenant_admin, tenant_staff; `PUT|DELETE /console/v1/business/products/{id}/picture` platform_admin, tenant_admin, tenant_staff; `GET /console/v1/media/{asset_id}` by the owning thing's read rule, anything else 404 (never 403), `training_thumbnail` always 404 there; `GET /console/v1/training/items/{id}/thumbnail` under the training gates. Audit actions `media.picture.set`, `media.picture.removed`.
- At most **one picture message per reply**; only for **Telegram** in slice 1 (WhatsApp, web sandbox and email get none; the text is unchanged). The image message is written **before** the text and both rows get `created_at = clock_timestamp()`.
- Image delivery rows: at most **two attempts**, then status `skipped` (already allowed by `outbound_deliveries_status_check`, `db/schema_baseline.sql:1096`; used today by `delivery/mark_suppressed.sql`) with `last_error` one of `picture_unavailable`, `picture_rejected`, `picture_failed`, written to the dead letters and the `dlq` staff notice like a dead row. Text rows keep `MAX_DELIVERY_ATTEMPTS = 5`.
- Outbound picture messages are **excluded from the model's history**; a held reply that staff approve later sends **text only**.
- Captions are built by code, never by the model: English `DuitNow QR: {label}`, Malay `QR DuitNow: {label}`; a plan's or product's caption is its name. Malay copy rules do not apply to these.
