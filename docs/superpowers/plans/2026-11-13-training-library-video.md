# Training Library Video Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A manager adds a video of up to 500 MB to the Training library in 8 MiB pieces that survive a bad connection; a separate training worker transcribes its audio with timestamps and writes one summary; staff watch it beside a clickable transcript and ask the workspace assistant about it with checked timestamps.

**Architecture:** Pieces go through the authenticated console route into S3 multipart parts (production) or positional writes into a local `.part` file (staging), with every piece hash checked again at completion. A new process, `python -m apps.training_worker.main` (same image, own compose service, own `training/` S3 key), claims one fenced job at a time, runs a hardened ffmpeg/ffprobe child per 5-minute audio chunk, sends each chunk to the existing `VOICE_STT_*` speech endpoint for segments, embeds 60-second windows through TEI, then map-reduces the summary. Playback is a 15-minute presigned GET on S3 and a gateway Range route on local; the assistant's read action `training_ask` answers from one video's transcript and is stored as `answer`.

**Tech Stack:** Python 3.12, FastAPI, psycopg 3 async with SQL under `db/sql/training/`, PostgreSQL migrations with RLS and pgvector, boto3 (moto and botocore Stubber in tests), ffmpeg/ffprobe, Groq JSON calls through `GroqClient.json_completion`, TEI embeddings (`DefaultKbEmbedder`), Next.js console (`CSA_WebConsole/csa-console/web/`), Playwright.

**Spec:** `docs/superpowers/specs/2026-11-13-training-library-video-design.md` (approved as written, including every "Calls made by the designer"; binds except where "Deviations from the design" below overrides it, each with its cost if wrong). Code facts are from a survey of main 76a4c71, re-checked against this branch; line numbers below are this branch's.

## Review Focus

- A resumed, duplicated or out-of-order piece never corrupts the file: same piece twice writes once, a piece with a wrong hash writes nothing, and a piece whose stored bytes no longer match its recorded hash is caught at completion and asked for again (Tasks 3, 5).
- The size, item and in-progress caps hold under concurrent starts, and a PDF failure's sweep never deletes a running video upload (Tasks 4, 5).
- A worker killed mid-job resumes at the next unfinished chunk or map part without duplicating segment rows, provider calls already committed, or the usage reservation; a stale attempt that wakes up after a re-claim cannot write (Tasks 6, 8, 9).
- Tenant isolation: every new table under row security as 0541; every object key and presigned URL is under `training/<caller's company>/`; company A reaches nothing of company B through any route, the worker or the assistant (Tasks 2, 3, 5, 6, 10, 11).
- The HR-owner manage rule through `training_is_hr_owner()` and `reader_may_post` are unchanged and cover every new route (Tasks 4, 5, 6).
- A failed, silent or soundless video never shows a summary (Tasks 8, 9, 12).
- The assistant never cites a timestamp outside what it sent the model, and never answers from another item or company (Task 11).
- Transcripts never reach the customer bot or the knowledge base (Task 11 test on `kb/search_chunks.sql`).
- Deletion in any state removes the file or `.part`, the S3 multipart upload, transcript, windows, summary, job and piece rows; only the usage row stays (Tasks 4, 6, 8).
- Money: at most 5 hours of processing per company per rolling 24 hours, reserved before the first billed chunk so a delete-and-reupload loop cannot escape it; a restart re-bills at most one 5-minute chunk (Tasks 6, 8).
- Staff assistant: a request for an HR training course still picks `training_submit`, a question about a video picks `training_ask` (Task 11 smoke).

## Deviations from the design

1. **The daily processing cap is reserved before the first billed chunk, once per item, instead of recorded after the last chunk; the cap check moves after the no-audio and silence checks.** As designed, a video deleted before its last chunk would never be counted, so a delete-and-reupload loop could transcribe without limit. Cost if wrong: a job that later fails permanently still counts its full length for 24 hours (at most one hour of the 5-hour allowance).
2. **Completion re-checks every piece against its recorded hash** (local: re-hash the `.part` by piece; S3: per-part `ChecksumSHA256` in the completion and `ListParts` on `InvalidPart`) and drops mismatched pieces for resending with 409 `training_piece_missing`. The design records a piece after writing it, so a crash between the two could otherwise complete a file whose bytes differ from the recorded hashes. Cost if wrong: about 1-3 s of hashing at completion on staging; one more 409 path in the client.
3. **The transcript fence is `<video_transcript>`** (fence word neutralised) instead of `<transcript>`, so a spoken "transcript" is not altered. Cost if wrong: none functional.
4. **The training worker's `oom_score_adj` is 600** (the workers keep 500), so the OOM killer takes a resumable video job before a customer-turn worker. Cost if wrong: under memory pressure video jobs restart more often, each repeating at most one chunk.
5. **The real-bucket presigned playback proof in Chrome and Safari becomes an owner retest row** before production's switch; the Range-through-rewrite proof stays the first step of the console task. The implementer has neither bucket access nor Safari. Cost if wrong: a Safari-only playback problem is found at retest, not during the build.
6. **`VOICE_STT_ENDPOINT` is set in compose for the training worker only** (the Groq URL, public), not by the rollout from a host file. Cost if wrong: changing provider needs a compose PR instead of an env edit.
7. **Production's training-worker S3 secrets fall back to the disabled placeholder** (as `CSA_STAGING_JEV_SECRET` does) so deploys keep working before the owner creates the key; with the switch on and the placeholder, the worker refuses to start. Cost if wrong: none while the switch is off.
