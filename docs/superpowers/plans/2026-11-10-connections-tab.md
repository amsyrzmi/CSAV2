# Connections Tab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One Connections tab where an Admin connects TikTok Shop for the company and every member connects their own Google Calendar and Gmail, with one look, one set of words, and every callback returning to it.

**Architecture:** Approach B of the spec: frontend only, plus the return page of the three callbacks. A new top-level `NavKey` `connections` with an admin route and a portal twin. A shared `ConnectionCard`/`ConnectionRow` draws every card. The connect, reconnect and disconnect code of the three existing components moves verbatim into three hooks; the tab is their only caller, and the old pages keep their status views and gain a "Manage in Connections" line. Pure rules (gates, words, return sentences) live in `lib/connections-view.ts`.

**Tech Stack:** Next.js 16.3 console (`CSA_WebConsole/csa-console/web`), node unit tests (`tests/*.test.mjs`), Playwright browser tests (`tests/*_browser.py`), FastAPI callbacks with pytest.

**Spec:** `docs/superpowers/specs/2026-11-10-connections-tab-design.md` (approved 2026-11-10, section 9 binding). Programme: `docs/superpowers/specs/2026-11-10-business-surfaces-programme.md` (PR 3, no migration).

## Global Constraints

- No migration, no new API, no change to scopes, tokens or the Google/TikTok redirect URIs. The only backend edits are the three callbacks' return pages; query parameter names and values stay: `tiktok=connected|failed` + `reason=<code>`; `calendar=connected` / `calendar_error=<code>`; `connected=1` / `error=<code>`, and TikTok's and Gmail's `client_id`.
- Return pages: TikTok `/connections?client_id=<state's company>` for a platform admin, else `/portal/connections`. Calendar always `/portal/connections`. Gmail keeps its own rule (`client_id` present: `/connections?client_id=…`, else `/portal/connections`).
- Route files are plain server components, as `app/(admin)/bookings/page.tsx`: `export default async function ConnectionsPage() { return <ConnectionsWorkspace me={await requireIdentity()} />; }`. They take no `searchParams` (a Promise in this Next; the client component reads `useSearchParams()` as `BusinessWorkspace` does).
- `proxy.ts` serves only listed pages: add `"/connections"` and `"/portal/connections"` after `"/portal/bookings/people-and-rooms"`. `"/portal/email",\n]);` must stay the last line of the list (`tests/test_kit_browser.py` patches it).
- Packages come from the existing `useActivePackages(scope)` (`components/console/overview/useActivePackages.ts`, `GET /services/active`): `""` for a member, the chosen company for a platform admin, `null` before one is chosen. A package unlocks a card only when `active`. `undefined` (loading) draws nothing; `null` (failed) draws the cards unlocked (the server's gates still refuse).
- Gates (spec 9): TikTok needs `marketplaces`; acting needs `tenant_admin` or `platform_admin`; `tenant_staff` sees status and a disabled Connect. Calendar needs `bookings` and `tenant_admin` or `tenant_staff`. Gmail needs `staff_email` and a role other than `read_only`. A platform admin sees only **Your business**. A `read_only` member's rows show a disabled button and no status, and the tab makes no stores, calendar or email read for them (the stores read refuses them anyway).
- Copy (exact). Heading "Connections", description "Connect fourstacks to your TikTok Shop and your own Google account, and see where each connection stands." Groups: "Your business" ("For the whole company. Only an Admin can connect or disconnect.") and "You" ("Your own Google account. Nobody else can connect it for you."). Cards "TikTok Shop" and "Google" (rows "Google Calendar", "Gmail"). Locked: "Included in the Marketplaces add-on.", "Included in the Bookings package.", "Included in the Staff email package." Role: "Your role can't connect this."; staff on TikTok: "Only an Admin can connect or disconnect a shop." (existing). No TikTok shop yet: word "Not connected", "Connect your TikTok Shop to sync its orders and products." Calendar off: word "Not switched on", "Google Calendar isn't switched on for this company yet. Ask your Admin."; not linked to a person: word "Not available", "Your account isn't linked to a person in Bookings yet. Ask your Admin to add you on People & rooms." Gmail connected: "Your Gmail {address} is connected to the Email assistant."; unknown Gmail return code: "Gmail could not be connected. Try again." Admin link on the Google card: "See your team's calendar connections". Old pages: "{name}: {word}." then the link "Manage in Connections". Every other state word, sentence, confirm question and return sentence is the existing one (`STORE_STATUS_WORDS`, `REASONS` and `connectResult` in `lib/tiktok-connect.ts`, `calendarStateWord`, `calendarResult`, the needs-reconnect banner, StatusBar's words, `emailErrorSentence`, "Mailbox connected.").
- Rail: label "Connections", after "Training library" and before the platform entries, lucide icon `Plug`, visible to every role, no gate. The assistant's `TabKey` is not extended (no prompt change; PR 5 changes navigation again).
- Tests one file at a time (`pytest <file> -q`, `node --test tests/<file>.test.mjs` from the web folder; in a worktree session through the `ci.sh` wrapper). Browser files only with more than 3 GB free memory. CI runs only changed test files: every browser file listed in a task is run by hand before pushing. Synthetic data only; the repository is public.

## Review Focus

- A platform admin's TikTok return lands on `/connections?client_id=<the state's company>`, never another company, and the parameters are unchanged (Task 2 backend test, Task 2 browser test).
- A return sentence shows once, then `tiktok`, `reason`, `calendar`, `calendar_error`, `connected`, `error` leave the address and `client_id` stays; it shows even when its card is hidden (Tasks 1, 2, 3).
- A read-only member and a platform admin make no `bookings/calendar/status` or `email/context` read; read-only makes no `business/stores` read either (browser stubs fail on unexpected calls, Task 3).
- A locked card shows its sentence and makes no status read (Tasks 2, 3).
- Old pages: no connect, reconnect or disconnect control left, every status kept (sync lines, sync-failing line, needs-reconnect banner, People & rooms team view, Email switch on/off and Sync) (Task 4).
- TikTok Connect still follows only a checked authorize URL (`navigate`), moved, not copied (Task 2).

## Deviations from the spec

- **Calendar has no "last activity"**: its status answer has no timestamp and the spec allows no API change. TikTok shows `syncLine(null, orders_synced_at)`, Gmail "Last checked …".
- **The old pages stop reading the return parameters**: the tab is the one reader; a bookmarked old return address still loads, without a sentence.
- **Switch on/off for the email assistant stays on the Email page**: it is a company setting, not a connection.
