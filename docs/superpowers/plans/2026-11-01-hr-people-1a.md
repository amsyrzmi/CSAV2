**Goal:** People & HR gets sub-tabs with their own URLs, every "More HR tools" tool moved into its tab with pickers, a Home page, a searchable People list, departments, an org chart, profiles (Overview, Access, History) with versioned edits, "Add person", My HR, and the new `manage_people` access switch.

**Architecture:**
- **Database (migration `0520_hr_people.sql`):**
  - New tables `hr_departments` and `hr_employee_changes`, plus four new `hr_employees` columns.
  - The free-text `department` column stays, as a mirror that triggers keep equal to the linked department's name. Every existing reader (directory projection, access page, workspace) keeps working unchanged.
  - A history trigger records old and new values for directory fields on every write path.
  - New SECURITY DEFINER reads project fields by viewer class (`hr`, `directory`, `self`).
  - The second write path is `hr_people_apply`, for owner or `people.manage` holders. `hr_admin_apply` is replaced to add the owner-only `account.link`.
- **Python:**
  - Pure rules in `csa/hr/people_rules.py`: status, S1 word search, filters, paging and the org chart.

- **Web:**
  - One optional catch-all route per audience (`app/portal/hr/[[...path]]`, `app/(admin)/hr/[[...path]]`).
  - Pure routing and tab rules live in `lib/hr-paths.ts`; the client shell and tab components live in `components/console/hr/`.

## Rulings this plan makes (the spec left them open)

- **People and the directory switch.** The People list and org chart need the complete directory switch (the `directory.read`/`hr_operator` grant with all five basic fields), or owner, or `manage_people`. Hand-made partial directory grants keep `/employees` but get no People tab.
- **Status.** The default status filter is Active and Starting (and Leaving in 1b). `status=left` is refused for non-HR viewers.
- **History and Access sections** are shown to the HR owner and Manage people holders. The "change on the access page" link and account linking are owner-only.
- **`person.update` never changes `is_active`.** Leaving and rehire are 1b.
- **Manager loops.** A save that would create one is refused (`manager_loop`). Existing loops show flat.
- **The legacy `department` text stays as a trigger-kept mirror.** `employee.save`, fixtures and every existing reader keep working.
- **Department names.** A department name stays taken while archived.
- **Settings is owner-only in 1a.** No Settings item is HR-team-only today.
- **The HR chat** sits collapsed on Home until 1b retires it. The raw "Access profile" form stays under Settings › Advanced. The separate Automation list is dropped, because the access page's Company features show the same switches.
- **Pickers.** Employee and member ids become pickers, as the spec requires. Interview, shift and payroll-request references also become selects over lists those tabs already load. The attendance correction reference stays typed.
- **Invitations.** The access-change and invitation switch bounds become 16, so 1b's `sensitive_details` needs no further function rewrite.
- **Not touched:** `lib/navigation.ts` and `components/AppShell.tsx`. The sidebar "People & HR" link only shows as current on `/portal/hr` itself (the `AppShell` exact match). The redesign's shell should use prefix matching.
